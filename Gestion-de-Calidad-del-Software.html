GESTIÓN DE LA CALIDAD DEL SOFTWARE

Fundamentos de calidad

Conocé los conceptos, métricas y estándares que permiten comprender y evaluar la calidad del software.

01 - conceptos

¿Que es la Calidad del Software?

La calidad del software se relaciona con su capacidad para cumplir los requisitos establecidos, funcionar correctamente y satisfacer las necesidades de sus usuarios.

La calidad no depende solamente del producto final. También está relacionada con la forma en que se desarrolla, se prueba y se mejora el software.

El material de Scrum destaca la relación entre los procesos y la calidad del resultado, y también señala la importancia del conocimiento y la experiencia de las personas que participan en el desarrollo

02 - Caracteristicas

Características de la Calidad

Estas características sirven como forma sencilla de explicar los aspectos que se evalúan al hablar de calidad

Funcionalidad

Acceso a los conceptos centrales de calidad aplicados al software.

Evalúa si el software cumple con las funciones necesarias para satisfacer las necesidades del usuario.

Fiabilidad

Una entrada a los procesos tradicionales y ágiles de desarrollo.

Indica la capacidad del software para funcionar correctamente y mantener un comportamiento estable durante su utilización.

Usabilidad

Un acceso inicial a metodologías relevantes para equipos ágiles.

Se relaciona con la facilidad con la que los usuarios pueden comprender, aprender y utilizar el software.

Eficiencia

Un acceso inicial a metodologías relevantes para equipos ágiles.

Evalúa el rendimiento del software y la cantidad de recursos que utiliza para realizar sus funciones.

03 - Medición

Metricas de Calidad

Las métricas permiten medir diferentes aspectos de la calidad de un software para conocer su comportamiento y detectar posibles problemas.

Rendimiento

Cómo responde el sistema y cuánto tarda en realizar operaciones.

Evalúa la velocidad de respuesta del software, el tiempo que necesita para realizar una tarea y la cantidad de recursos que utiliza.

Fiabilidad

Frecuencia de errores o fallos del sistema.

Indica la capacidad del software para funcionar correctamente durante un período determinado sin presentar fallos.

Usabilidad

Qué tan fácil resulta utilizar el software.

Se relaciona con la facilidad para aprender, comprender y utilizar el software de manera sencilla y eficiente.

Mantenibilidad

Qué tan fácil es modificar o corregir el software.

Evalúa qué tan sencillo resulta encontrar errores, realizar cambios y adaptar el software a nuevas necesidades.

La familia SQuaRE incluye estándares específicos relacionados con la medición de la calidad de productos de software.

04 - Desarrollo

Calidad en el desarrollo de Ágil

Cómo se construye calidad mientras se desarrolla, según el material de Scrum.

Mejora Continua

El desarrollo ágil busca revisar constantemente el trabajo realizado para detectar problemas y realizar mejoras. En Scrum, las iteraciones permiten analizar el producto y la forma de trabajo para decidir qué mantener, modificar o mejorar.

Pruebas

Una forma de prevenir errores es utilizar pruebas durante el desarrollo. El material presenta TDD (Test Driven Development), donde primero se desarrollan las pruebas que debe superar el código y después se desarrolla el código correspondiente.

Calidad de Producto

En Scrum, la calidad también se relaciona con el conocimiento, la experiencia y la creatividad de las personas que forman parte del equipo.

Técnicas de Aseguramiento de la Calidad

Las pruebas de software son una parte fundamental de la verificación y validación. Permiten comprobar el software y detectar errores antes de su puesta en funcionamiento. También existen técnicas estáticas, como las inspecciones, que permiten analizar documentos, diseños y código sin ejecutar el programa.onocé los conceptos, métricas y estándares que permiten comprender y evaluar la calidad del software.

01 - Niveles

Niveles de pruebas

01

Pruebas unitarias

Una unidad por vez

Se realizan sobre unidades individuales del software para comprobar que cada una funcione correctamente de acuerdo con su especificación.

Objetivo:

Verificar cada componente de manera independiente.

02

Pruebas de integración

Componentes en conjunto

Se realizan cuando diferentes componentes se integran para comprobar que funcionen correctamente en conjunto.

Objetivo:

Detectar problemas en la interacción entre componentes.

03

Pruebas de sistema

El sistema completo

Se prueba el sistema completo para comprobar que sus componentes funcionen correctamente y que cumpla con los requisitos establecidos.

Objetivo:

Verificar el funcionamiento del sistema completo.

02 - Tipos

Tipos de pruebas

Caja Negra

Lo que hace el software

Se prueba el comportamiento del software sin tener en cuenta
cómo está implementado internamente.

Se analiza:

  • Entradas
  • Salidas
  • Comportamiento esperado

Caja Blanca

Cómo funciona por dentro

Se basa en conocer la estructura interna del programa
para diseñar las pruebas.

Se analiza:

  • Código
  • Caminos de ejecución
  • Estructuras internas

03 - Más Técnicas

Otras Técnicas relacionadas

Inspecciones

Son técnicas estáticas de verificación y validación. Permiten analizar requerimientos, modelos de diseño, código fuente y otros documentos sin ejecutar el software.

Pruebas de usuario

Los usuarios o clientes participan proporcionando información y realizando pruebas sobre el sistema. Sommerville distingue pruebas alfa, beta y de aceptación.

Herramientas de Calidad

Las herramientas de calidad ayudan a los equipos de desarrollo a controlar diferentes aspectos del software, como el seguimiento de errores, el análisis del código y la organización de las pruebas.

01 - Categorías

Tres piezas de calidad

Elegí una categoría para ver las herramientas relacionadas.

01

Bug Trackers

Seguimiento de defectos

Herramientas utilizadas para registrar, organizar y realizar el seguimiento de los errores o defectos que se encuentran en un software.

Permiten registrar:

  • Descripción del error
  • Estado del defecto
  • Prioridad
  • Persona responsable
  • Seguimiento de su resolución

¿Para qué sirven? Ayudan a mantener organizados los errores y a controlar su resolución durante el desarrollo.

02

Linters

Análisis del código

Herramientas que analizan el código fuente para detectar posibles errores, problemas de estilo o construcciones que puedan generar inconvenientes.

Para qué sirven:

  • Detectar errores potenciales
  • Mantener un código más ordenado
  • Aplicar reglas de estilo
  • Mejorar la calidad del código

¿Para qué sirven? Revisan el código de forma automática y avisan sobre problemas antes de que lleguen a ejecutarse.

03

Test Management

Gestión de las pruebas

Herramientas destinadas a organizar y gestionar las pruebas de software durante todo el proceso de verificación.

Permiten organizar:

  • Casos y planes de prueba
  • Ejecución de las pruebas
  • Resultados obtenidos
  • Seguimiento de defectos

¿Para qué sirven? Ayudan a planificar las pruebas y seguir su avance durante el proceso de verificación.

03 - En conjunto

Las tres se complementan

Los bug trackers registran

Dejan constancia de cada defecto y de quién debe resolverlo, para que ningún problema quede sin seguimiento.

Los linters previenen

Revisan el código mientras se escribe y ayudan a que los errores aparezcan lo antes posible

El test management organiza

Concentra los casos de prueba, las ejecuciones y sus resultados para saber cómo va la verificación
