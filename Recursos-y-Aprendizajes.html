La calidad del software se relaciona con el grado en que un sistema cumple con los requisitos establecidos y satisface las necesidades de sus usuarios. Para evaluarla se pueden utilizar características, métricas y técnicas de aseguramiento de la calidad.

Es una representación simplificada de un proceso de software. Los modelos permiten organizar y representar las actividades que se realizan durante el desarrollo.

Es un modelo de desarrollo en el que las actividades se organizan en etapas. Entre ellas se encuentran la definición de requerimientos, el diseño, la implementación, las pruebas y el mantenimiento.

Es un enfoque en el que el sistema se desarrolla y entrega mediante diferentes incrementos. Cada incremento incorpora nuevas funcionalidades hasta llegar a una versión completa del sistema.

Scrum es una metodología ágil que organiza el desarrollo del producto mediante ciclos de trabajo llamados Sprints, permitiendo entregar incrementos del producto y recibir retroalimentación de manera frecuente.

Es un período de tiempo limitado durante el cual el equipo trabaja para desarrollar un incremento del producto. En Scrum, un Sprint puede durar hasta cuatro semanas.

EJERCICIO 01 · MODELO EN CASCADA E INCREMENTAL

Modelos de desarrollo

01
ENUNCIADO

Una empresa necesita desarrollar un sistema cuyos requisitos están claramente definidos y es poco probable que cambien durante el proyecto. ¿Qué modelo podría utilizar y por qué?

SOLUCIÓN ORIENTATIVA

El modelo más adecuado es Cascada. Como los requisitos están bien definidos y son estables, el equipo puede avanzar de una etapa a la siguiente —requisitos, diseño, implementación, pruebas y mantenimiento— sin volver constantemente sobre decisiones anteriores. Si los requisitos fueran inciertos o cambiaran con frecuencia, convendría un enfoque incremental que permita incorporar ajustes entre entregas.

EJERCICIO 02 · NIVELES DE PRUEBA

Pruebas de software

02
ENUNCIADO

Un equipo desarrolla una aplicación de turnos. Primero comprueba que el formulario valide correctamente los datos, después verifica que el formulario y la base de datos funcionen juntos y, finalmente, prueba toda la aplicación. Identificá los tres niveles de prueba en orden.

SOLUCIÓN ORIENTATIVA

En orden: prueba unitaria, prueba de integración y prueba de sistema. La primera revisa el formulario de manera aislada; la segunda comprueba la interacción entre el formulario y la base de datos; y la última evalúa la aplicación completa como un producto integrado.

EJERCICIO 03 · EVENTOS DE SCRUM

Scrum

03
ENUNCIADO

Durante un Sprint, el equipo se reúne diariamente para revisar el avance e identificar impedimentos. Al finalizar, presenta el incremento desarrollado y luego reflexiona sobre cómo mejorar su forma de trabajar. ¿Qué eventos está realizando?

SOLUCIÓN ORIENTATIVA

Primero realiza el Daily Scrum para inspeccionar el progreso y adaptar el plan de trabajo. Al terminar el Sprint, lleva a cabo la Sprint Review para inspeccionar el incremento con las partes interesadas y, después, la Retrospectiva para acordar mejoras en la forma de trabajar.

EJERCICIO 04 · GESTIÓN VISUAL DEL TRABAJO

Kanban y límite WIP

04
ENUNCIADO

Un tablero Kanban tiene un límite WIP de 2 tareas en la columna “En proceso”. Ya hay dos tareas en esa columna y un integrante quiere comenzar una tercera. ¿Qué debería hacer el equipo?

SOLUCIÓN ORIENTATIVA

El equipo no debería iniciar una tercera tarea porque ya alcanzó el límite WIP. Conviene colaborar para terminar o desbloquear una de las tareas en curso; cuando una pase a la siguiente columna y haya espacio disponible, podrán tomar nuevo trabajo. Así se limita el trabajo simultáneo y se favorece un flujo más constante.
